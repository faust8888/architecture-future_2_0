# Расширенный технический радар «Будущее 2.0»

Радар объединяет **технологии** и **архитектурные паттерны**. Статусы по смыслу ThoughtWorks Radar:

| Статус | Значение |
|--------|----------|
| **Adopt** | применять по умолчанию для новых решений |
| **Trial** | пилотировать на ограниченном периметре |
| **Assess** | изучать, Proof of Concept, без массового продакшена |
| **Hold** | не расширять; планировать вывод или изоляцию |

---

## Кольцо Adopt

| Элемент | Тип | Комментарий |
|---------|-----|-------------|
| Event-Driven Architecture (EDA) | паттерн | основной контракт между доменами |
| Domain-Driven Design (DDD), bounded contexts | паттерн | границы владения и интеграций |
| Infrastructure as Code (Terraform и др.) | паттерн | воспроизводимые среды |
| CI/CD с approval для prod | паттерн | безопасные релизы платформы данных |
| Объектное хранилище + форматы открытых таблиц (Parquet / Delta / Iceberg)* | технология | lakehouse-слой |
| Управляемый Kubernetes / контейнерная платформа | технология | runtime для доменных сервисов |
| Kafka-совместимая шина событий (управляемый кластер) | технология | брокер событий |
| OpenTelemetry | технология | единая наблюдаемость |
| RBAC / SSO (OIDC), секреты в Vault-классе решений | технология | базовый периметр безопасности |

\*Конкретный движок lakehouse (Spark / Flink / Trino / managed SQL) — см. Trial/Assess в зависимости от облака.

---

## Кольцо Trial

| Элемент | Тип | Комментарий |
|---------|-----|-------------|
| Data Mesh (федеративная модель, data products) | паттерн | пилот 1–2 домена |
| Data Contracts + Schema Registry | паттерн | версионирование событий и качества |
| Self-service BI + семантический слой | паттерн | витрина без PHI в смысле кейса |
| CQRS / read-модели на событиях | паттерн | отчётность и витрины |
| Stream processing (Flink / managed streaming) | технология | near-real-time витрины |
| dbt или аналог для трансформаций в warehouse/mart | технология | стандартизация витрин |
| Feature Store / MLOps-контур | технология | контролируемый жизненный цикл ИИ |
| CDC (Debezium / managed CDC) | технология | инкрементальная синхронизация из легаси |

---

## Кольцо Assess

| Элемент | Тип | Комментарий |
|---------|-----|-------------|
| Политики данных как код (OPA / каталог + ABAC) | паттерн | усиление PHI / финрегуляторики |
| Data lineage automation | технология | глубокий аудит потоков |
| Multi-region active-active для брокера | технология | географическое масштабирование |
| Замена легаси BI-тяжестей на headless semantic layer | паттерн | зависит от текущих кастомизаций Power BI |

---

## Кольцо Hold

| Элемент | Тип | Комментарий |
|---------|-----|-------------|
| Расширение бизнес-логики в центральном DWH SQL Server 2008 | паттерн | только поддержка; новые кейсы не добавлять |
| Точечная синхронная «паутина» через ESB без событий | паттерн | ограничить; новые интеграции не через Camel как основной путь |
| Ручные Excel-конвейеры как система учёта | паттерн | выводить в governed pipelines |
| Долгие batch-only отчёты без SLAs для критичных метрик | паттерн | замещать потоковыми витринами там, где нужно |

## Визуализация (для презентации)

Один из вариантов: перенести таблицы в инструмент радара ([radar.thoughtworks.com](https://www.thoughtworks.com/radar)-подобные шаблоны, Miro) или построить квадрант в Draw.io: оси «зрелость / риск» и четыре кольца.

Дополнительно можно отобразить связь радара с доменами из `Task4Advanced`: Trial для Data Mesh совпадает с клиниками/финтехом-пилотом.
