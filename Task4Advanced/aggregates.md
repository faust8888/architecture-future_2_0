# Агрегаты по bounded contexts

Ниже — **ключевые агрегаты**, через которые домены сохраняют целостность и публикуют события наружу. Это не полная модель данных, а опорные границы для интеграций.

---

## Клиники

### Контекст: Patient Identity / Registration

| Элемент | Описание |
|--------|----------|
| **Корень агрегата** | `Patient` |
| **Идентификатор** | `PatientId` (UUID), внешний `MedicalRecordNumber` (опционально) |
| **Состав** | контактные атрибуты для записи (не дублировать PHI во внешних топиках), статус регистрации, привязка к юридическому лицу клиники |
| **Инварианты** | один активный MRN на пациента в пределах клинической сети; изменение идентификаторов только через доменный сервис |
| **События наружу** | `PatientRegistered`, `PatientDemographicsUpdated` (минимальный состав полей по политике) |

### Контекст: Appointment & Visit Management

| Элемент | Описание |
|--------|----------|
| **Корень** | `Visit` (или `Appointment` до факта прихода → `Visit`) |
| **Идентификатор** | `VisitId` |
| **Состав** | слот времени, статус визита, ссылка на `PatientId`, тип приёма |
| **Инварианты** | нельзя закрыть визит без отметки начала; двойное бронирование слота блокируется политикой |
| **События** | `VisitScheduled`, `VisitStarted`, `VisitCompleted` |

### Контекст: Clinical Documentation (PHI)

| Элемент | Описание |
|--------|----------|
| **Корень** | `ClinicalEncounter` или `CareEpisode` (выбирается одна модель как корень долгоживущего случая) |
| **Идентификатор** | `EncounterId` |
| **Состав** | протоколы, назначения, результаты исследований — **остаются внутри контекста** |
| **Инварианты** | юридический срок хранения; доступ только через RBAC/ABAC клиники |
| **События наружу** | только **обезличенные или категориальные**: например `ClinicalOrderPlaced` (тип услуги, без диагноза в payload для Mart) |

## Финтех

### Контекст: Accounts & Ledger

| Элемент | Описание |
|--------|----------|
| **Корень** | `Account` |
| **Идентификатор** | `AccountId`, номер счёта как value object |
| **Состав** | балансы по субсчётам (если нужно), статус, владелец (ссылка на `PartyId`) |
| **Инварианты** | двойная запись или эквивалентная модель проводок внутри агрегата `LedgerEntry` под транзакцией |
| **События** | `AccountOpened`, `AccountBalanceThresholdCrossed` |

### Контекст: Payments & Settlements

| Элемент | Описание |
|--------|----------|
| **Корень** | `PaymentOrder` |
| **Идентификатор** | `PaymentId` |
| **Состав** | сумма, валюта, статус конечного автомата, связь с `AccountId`/мерчантом |
| **Инварианты** | идемпотентность по `ClientRequestId`; финальный статус необратим без компенсирующей операции |
| **События** | `PaymentAuthorized`, `PaymentCaptured`, `PaymentFailed` |

### Контекст: Lending / Credit Agreement

| Элемент | Описание |
|--------|----------|
| **Корень** | `CreditAgreement` |
| **Идентификатор** | `AgreementId` |
| **Состав** | условия, график, статус договора, связь с заёмщиком (`PartyId`) |
| **Инварианты** | нельзя активировать без скоринга и проверки лимита в том же транзакционном блоке домена |
| **События** | `CreditAgreementCreated`, `CreditAgreementActivated`, `InstallmentDue` |

## ИИ

### Контекст: Diagnostic Assistance / Inference Session

| Элемент | Описание |
|--------|----------|
| **Корень** | `InferenceSession` |
| **Идентификатор** | `SessionId` |
| **Состав** | ссылки на входные данные **по политикам клиники** (часто внутренние идентификаторы без экспорта наружу), версия модели, статус |
| **Инварианты** | каждый вывод трассируется к версии модели и времени; PHI не покидает контур без маскирования |
| **События** | `AISessionRequested`, `AIDiagnosticHypothesisRecorded`, `AISessionCompleted` |

### Контекст: Model Lifecycle & Governance

| Элемент | Описание |
|--------|----------|
| **Корень** | `MlModelRelease` |
| **Идентификатор** | `ModelReleaseId` |
| **Состав** | артефакты, метрики качества на hold-out, статус промоушена |
| **Инварианты** | продакшен только после подписания комплаенс-гейта |
| **События** | `MlModelPromotedToProduction`, `MlModelRetired` |

## Данные и аналитика

### Контекст: Integration Contracts

| Элемент | Описание |
|--------|----------|
| **Корень** | `EventTopicContract` (или версионированная схема Avro/JSON Schema в каталоге) |
| **Идентификатор** | `SchemaId` + semver |
| **Инварианты** | обратная совместимость или явная миграция топика |
| **Роль** | **Open Host Service** для доменных топиков |

### Контекст: Analytics Mart & Semantic Layer

| Элемент | Описание |
|--------|----------|
| **Корень** | полубесконечные read-модели / витрины без классического «агрегата записи»; граница — **dataset / cube / semantic metric** |
| **Инварианты** | запрет полей PHI по классификации; только события и справочники из разрешённых источников |

## Легаси (переход)

### DWH Legacy Bridge / Camel

Агрегаты не являются «ядром продукта»; это **адаптеры**. Инвариант — не расширять бизнес-логику в DWH при добавлении новых доменов; только репликация и совместимость.
